Como converter XML de NFS-e em PDF

Leitura: 7 min Nível iniciante Atualizado em maio de 2026

Converter um arquivo XML de NFS-e em PDF (DANFSe) é uma das tarefas mais comuns para quem trabalha com notas fiscais — seja para arquivamento visual, envio ao tomador, conferência pelo contador ou apresentação em fiscalização. Apesar de parecer trivial, na prática surgem dúvidas: posso fazer em lote? Preciso de programa? É seguro enviar XMLs para sites desconhecidos?

Este artigo responde essas perguntas e apresenta o caminho mais prático e seguro para converter XMLs em PDF, individualmente ou em grandes lotes.

O que é a conversão XML → PDF

Antes de qualquer coisa, vale lembrar: o XML é a nota fiscal. O PDF (DANFSe) é apenas sua representação visual — útil para humanos lerem, mas sem substituir o XML para fins fiscais. Quando convertemos XML para PDF, estamos traduzindo aqueles dados estruturados em um documento amigável, com layout padronizado pelo CGNFS-e.

A conversão não altera o XML original. O PDF gerado contém todos os dados relevantes — prestador, tomador, valores, retenções, descrição do serviço, QR Code de consulta — em um layout institucional reconhecido pela Receita.

Caminhos possíveis para converter

Existem três caminhos principais. Cada um tem trade-offs diferentes em termos de praticidade, custo, e principalmente segurança dos seus dados:

  1. Pelo portal oficial (nfse.gov.br) — consulta-se a NFS-e pela chave de acesso e o portal mostra a DANFSe. Funciona só para uma nota por vez, e exige que a NFS-e já esteja registrada no sistema central.
  2. Pelo sistema emissor — Bling, Conta Azul, ERP próprio: se você emitiu a nota lá, normalmente tem botão para baixar o PDF. Limitação: só funciona para suas próprias notas, não para XMLs recebidos de terceiros.
  3. Por uma ferramenta conversora — recebe um ou vários XMLs e devolve PDFs. Ideal para tomadores que recebem notas de prestadores, para contadores que precisam processar XMLs em volume, e para arquivamento.

Por que segurança importa nessa escolha

XMLs de NFS-e contêm dados sensíveis: CNPJ de prestador e tomador, descrição do serviço, valores. Ao usar uma ferramenta online de conversão, você precisa avaliar: esses dados estão sendo enviados para um servidor remoto? Onde ficam armazenados?

A maioria dos conversores online faz upload do XML para o servidor deles, processa, e devolve o PDF. Funciona, mas significa que seus dados fiscais transitaram por terceiros — algo que pode violar políticas internas da sua empresa, especialmente em escritórios contábeis com cláusulas de confidencialidade com clientes.

Passo a passo: convertendo um XML

Para uma única nota, qualquer dos três caminhos resolve. Se você optar pelo nosso conversor (que funciona 100% no navegador, sem upload), o processo é direto:

  1. Acesse a ferramenta no link acima (ou pelo menu “Converter” no topo do site).
  2. Clique no botão de seleção de arquivos e escolha o XML no seu computador.
  3. O nome do arquivo aparece logo abaixo, confirmando que foi reconhecido.
  4. Clique em “Converter para PDF”. Na primeira vez pode demorar 20-40 segundos (carregando o ambiente Python no navegador); depois é instantâneo.
  5. O PDF é baixado automaticamente para a sua pasta de Downloads, com o nome DANFSe_[chave_de_acesso].pdf.

Passo a passo: convertendo em lote

Para quem recebe muitas notas — contadores, escritórios, departamentos financeiros — converter uma por vez é impraticável. O lote resolve. Funciona assim:

  1. Selecione vários arquivos XML de uma vez (segure Ctrl ou Shift na hora de selecionar no Windows; Cmd no Mac).
  2. Todos aparecem listados na ferramenta, numerados.
  3. Clique em “Converter para PDF”.
  4. A barra de progresso mostra a conversão acontecendo arquivo por arquivo.
  5. Ao final, todos os PDFs são empacotados em um único arquivo .zip, baixado para Downloads.

Recomendamos lotes de até 100 arquivos por vez para manter a interface responsiva. Para volumes maiores, divida em lotes — não há limite total de uso.

O que verificar no PDF gerado

Após gerar a DANFSe, faça uma conferência rápida antes de arquivar ou enviar:

  • Número da NFS-e e chave de acesso conferem com o XML
  • CNPJ do prestador e do tomador estão corretos
  • Valor do serviço e valor líquido fazem sentido
  • Retenções (se houver) aparecem em destaque vermelho
  • QR Code de consulta está visível
  • Município emissor está identificado

Erros comuns e o que fazer

Se a conversão falhar, na maioria dos casos é porque o arquivo XML não está no padrão NFS-e Nacional (CGNFS-e). XMLs do padrão municipal antigo (ABRASF) têm estrutura diferente e precisam de um conversor específico.

Outros problemas comuns: arquivos corrompidos (download interrompido), XMLs editados manualmente que invalidaram a estrutura, ou XMLs ainda em rascunho que não foram efetivamente assinados. Em qualquer caso, a recomendação é validar o arquivo no portal nacional antes de tentar a conversão.
